# Codex `/goal`：Unreal 资产交付验收台长期开发

下面是本仓库可直接恢复、可跨上下文压缩持续执行的唯一长期目标提示词。完成的 v0.8
产品化历史保留在 `artifacts/goal/checkpoint-0015.json`。

```text
/goal

只开发 D:\3D\_tools\unreal-asset-batch-auditor，不修改 Art Pipeline Skill、AIToolTA 或其他仓库。

持续把 Unreal Asset Batch Auditor 开发成面向国内 TA 求职展示和真实美术团队交付的中文原生
Unreal Editor 资产验收台：Profile 决定标准，C++ 采集宿主事实，Python 负责编排、判定、报告、
会话和交接。默认只读，不依赖 AI，不为炫技制造无业务价值的复杂度。

每轮恢复顺序固定为：AGENTS.md；config/goal-state.json；lastCheckpoint 指向的不可变检查点；
本文件与 CODEX_LOOP.md；最后读取 git 状态、最近提交和 nextSlice 涉及的真实代码。随后运行
scripts/goal.ps1 -Action Doctor。goal-state 是唯一当前状态源，checkpoint 只记录历史；冲突时
先修状态，不根据聊天记忆猜进度。每轮只推进 nextSlice。

开发节奏：
- 状态回顾限于一次有目标的快速盘点，不重复审计未变化模块，不为了“更稳”无限增加测试；
- 优先完成一个用户可感知、能录屏、能解释业务价值的纵向切片；
- 保留 Unreal 原生工作流和高信息密度，以“交付批次 / 范围校准 / 风险谱 / 证据台账”为概念；
- 禁止套用 AI 聊天框、助手头像、魔法星光、紫蓝渐变和空泛智能建议等产品套路；
- 工作区存在他人改动时保留并绕开，不回滚、不覆盖。

风险分级门禁：
- 纯文档或纯 Python 小改：只跑相关 pytest 与 Ruff；
- C++、Slate、采集边界变化：跑 quick validation、一次 BuildPlugin、一次独立 UE 短生命周期烟雾；
- 可见界面变化：补当前版本关键截图，不重复拍摄没有变化的旧流程；
- 正式发布：才执行干净安装、升级、确定性打包、校验和与完整发布验证。
同一切片通常只做一次开发前最小检查和一次结束验收，不循环重跑完整套件。

真实 Unreal 测试必须使用独立、隐藏、带超时的短生命周期进程。启动前记录已有 Unreal PID，
只清理本轮创建且能确认归属的 PID；不得附着、切换、关闭或复用用户已有 UE 会话。

证据边界：fixture 不等于 Unreal 宿主验证；BuildPlugin 不等于交互成功；单一 UE 版本不等于
跨版本兼容；小样本不等于生产规模无卡顿；计划和 README 不等于已实现。

产品原则：所有阈值来自版本化 Profile；范围由用户显式选择；问题能回到资产、规则、实测、
阈值和 Evidence；采集失败进入报告；大批量任务提供进度、批次间取消、稳定排序和合法部分结果。
自动修复若未来立项，必须独立里程碑、先生成 ChangeSet、用户确认、再执行与复检。AI 只有在
明确降低规则配置、解释或交接成本时才可作为辅助，确定性规则仍是最终判定。

切片完成后更新当前文档和必要证据，写入下一个编号 checkpoint，原子推进 goal-state revision、
里程碑和唯一 nextSlice，最后提交并推送。失败记录实际边界和最小恢复条件；只有同一阻塞连续
三轮且无法继续时才标 blocked。长期目标不会因为一个版本发布而结束，只有用户明确终止时结束。
```
